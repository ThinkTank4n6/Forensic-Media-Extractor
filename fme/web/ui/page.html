Hash sets

1  Connect to the hash store

A store holds every hash set you have imported and is kept between cases. It is either a file on this machine, or a server your unit shares — a server needs the token you were issued and, for a lab certificate, a copy of that certificate.

On, so the store is simply there each morning: the token is written to a file this Windows account can read, and anyone who can read it can use the store as you. Turn it off on a machine others log into, and you will paste the token once per session instead.
not connected
2  Check this case against the store

Needs a case open: a finished run, or one opened from the Cases list. A Project VIC match carries the category that set recorded; an NSRL match means known software, which is usually a reason to set a file aside rather than examine it. Nothing here decides what a match means.

A set for this session only — loaded here, used for checking, and gone when the program closes. For a set you will use again, import it into the store above instead.

3  Add this case to the store

Sends the hashes of the files you have categorized, with the category you gave them, so the next case meets them already known. Only graded files are sent, and only hashes and labels — never a picture, and never the file itself.

Similar media

Three ways of relating files to each other that a hash cannot: a hash changes completely when one pixel does. All of these need a finished run, and they write their results into the case.

Visually similar images

Groups pictures that look alike even when their bytes differ — a re-saved JPEG, a resized copy, a screenshot of the same image. Similar is a judgment, not a fact: the distance is shown for every match so you can see how close it really is.

Stills and the videos they came from

A picture and the video it was taken from share no bytes, so no hash relates them — but a frame of that video and the picture are the same image. This hashes each video's key frames and matches the stills against them, so a screenshot finds its source, and a video shows what was taken from it. Needs Pillow and OpenCV.

Screening to decide what to look at first

Measures how much of each picture sits in a broad skin-tone color band, and counts faces where OpenCV is installed. This is arithmetic over pixels, not a nudity classifier: sand, wood and a close-up of a face score high, a clothed subject and a dark photograph score low, and nothing is categorized by it. It adds two filters so a backlog can be worked in a useful order.

Point this at one or more local sample files of a format the built-in list doesn't cover, and it computes the byte pattern the carver can match on. Give multiple samples of the same type when possible — the "common to all samples" row is far more reliable than trusting one file's header/footer, since a single sample can include bytes that vary between files (timestamps, random IDs, etc).
